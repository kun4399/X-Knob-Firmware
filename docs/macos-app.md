# macOS 菜单栏软件：实现与验证

2026-10-24，Mac 端由独立 LaunchAgent 迁移为 `X-Knob Companion.app`。只改 Mac 端与相关文档，没有改动或重新烧录本轮此前的旋钮/网关固件。

## 当前行为

- AppKit 菜单栏旋钮图标，`LSUIElement=true` 并使用 accessory 激活策略；Dock 不常驻图标。
- 原生 MQTT 设置窗口：地址、端口、用户名、钥匙串密码、TLS；高级设置保留旋钮配对标识和原有 SSH 接入方式。
- 保存后重连；可停止/重新连接。关闭设置窗口继续运行，退出软件会结束本应用的引擎与 SSH 转发。
- 应用内安装/卸载六类重要 Hooks。安装前显示具体事件说明；旧项目布局和旧应用的注册会被清理，其他 Hooks 保留，变更前独立备份。
- Hooks 改为同一应用中的原生 `--hook` 入口，不再依赖仓库目录、venv 或每次启动 Python。仅转发白名单元数据，停止/异常时快速返回。
- 打包 Python 引擎保留已有状态归约、120s 保活、MQTT ACL 边界和账号适配器。用户运行应用不需要终端或另装 Python。

## 已完成的真实迁移

- 初始用户 Hooks 共 14 条本项目注册，其中旧 `1.Firmware/mac_companion` 下 8 条指向已不存在脚本。已清理这 8 条，并将有效的六条迁移至已安装应用。
- 最终每类重要事件恰好一条，无 PreToolUse/PostToolUse 残留，无失效目标路径。信任状态没有被修改；Codex 对新定义的审核仍由客户端处理。
- 原 `local.xknob.companion` LaunchAgent 已私下备份后停用、移除。现有 MQTT 设置、SSH 路径、配对标识与钥匙串密码保留；没有新建自动登录项。
- 应用已复制至用户的应用程序目录；独立于终端运行，真实 MQTT 连接成功，健康接口确认实际后台 PID 与连接状态。
- 应用约 20MB，为当前 Apple Silicon / macOS 27 的本机构建；最低系统版本来自包内依赖的真实 Mach-O 部署目标，不推断其他系统兼容性。

## 验证

- 20 项 Python unittest 通过：含旧路径/删除应用清理、混合组保留、重复安装与卸载、配置校验、配置迁移与文件权限。
- 对实际 `.app` 进行了独立测试：安装/重复安装/卸载保留其他配置；原生 helper 不转发提示词/命令/输出，Stop 返回空 JSON，服务离线和坏输入不阻止调用方。
- 实际打包引擎在隔离端口和临时配置下通过健康 PID、HTTP 鉴权、事件接收、SIGTERM 正常退出，合成事件没有发送到真实 broker。
- 本机签名及深层严格签名校验通过；应用自检通过。
- 原生设置窗口已实际打开并检查布局；无效端口 0 被拦截，恢复后保存、重连成功；密码输入保持掩码。
- 已实际验证原生父进程结束后，后台 HTTP 入口与 SSH 转发都关闭，没有由旧 LaunchAgent 重启。
- 最后一次菜单/窗口“退出并重新打开”的点击验证因 Mac 锁屏暂未完成；不把后端 SIGTERM 和父进程退出测试描述为已完成该界面点击测试。

构建与使用说明见 [Mac Companion](../macos/companion/README.md)。所有私有配置、备份、凭据、打包产物和本机截图均未加入版本控制。
