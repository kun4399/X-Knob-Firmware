# Always Ready 12h v3：实施与验收记录

2026-10-24，软件改造已合入 X-Knob 与独立 SmartLED 网关工作树，两块板均完成烧录与写入校验。经用户审阅批准，已更新本项目 Hooks 并重启现有 Companion。网关已通过本版真实 BLE 回读与同值命令测试；用户已确认新版开关手感、黑屏直控和按压唤醒正常。**12 小时仍是目标；电池电流、真实开关延迟 P95 和三组续航尚未实测。**

## 规范与合入范围

按交付包的[完整 v3 规范](always-ready/implementation-spec-v3.md)实施。用户实机体验后追加要求：亮屏主页要像开关一样只有一次跨档，而不是连续旋转卡位。因此当前主页改用既有两端位开关模式，替代原规范的无界主页卡位；黑屏无电机输出和方向式控灯仍保持。该文件是未改写的输入规范，不是本轮的完成报告；原始 SHA-256 为 `ccb7fcd8ba06aeafffc4618cfd06fc958f464da8dc1ee55eecd8fa80b1861c87`。交付包 SHA256SUMS 全部通过。两个工作树在合入前均干净；先进行覆盖层 dry-run、patch dry-run 和原文件备份，再合入覆盖层。包内 patch 将现有 RGB 文件标成新增，与当前仓库不同；以逐文件对比后的 overlay 为准，没有重复套用 patch。

## 集成时修正的覆盖层缺口

覆盖层本身不等于可验收固件。本轮另修正了：SimpleFOC 2.2.3 没有 PID reset 接口、唤醒 shaft_angle 停留在黑屏前、暗屏方向未使用 FOC 校准极性、模式重设位置被误认旋转、旧 LVGL 设置入口抢输入、灯控页 ACK 假确认、旧意图唤醒/断网后重试、精调双击路由、启动 RGB 未限亮度、历史通知基线、Mac 解释器或目录变化后旧 Hooks 遗留，以及中文缺字。实机部署前还发现公开主机 ID 占位符与现有 Companion 不匹配，已增加 ignored secrets.h 的构建覆盖入口，并验证最终镜像使用本机路由值；该值未写入受版本控制文件。

状态通知须同步升级 Companion 与旋钮。旧 Companion 仍可提供显示状态，但缺少事件高水位时固件会静默处理提醒，以避免重放历史审批。用户另行批准具体 Hooks 方案后，已原子更新个人配置并保存私有备份，只移除本项目两个工具 Hooks，其余配置不变；现有 Companion 重启后健康检查通过，随后真实 Hooks 事件计数继续增长。没有新增系统自启动项。

## 本版部署与真实链路证据

- 用户将两块板连接后，芯片型号和容量均通过只读探针确认。完整备份、分区一致性核对、写入摘要验证已完成；设备标识、端口、凭据和原始输出未进入仓库。
- 网关串口捕获到本版 MIoT BLE 登录成功和属性回读，观察窗口内没有 panic/watchdog。Mac 直连 broker 暂无路由；经现有 Companion 本地隧道收到非 retained 的新鲜 `device_readback`，不是把旧 retained 状态当新验证。
- 一次保持原电源值的 V1 命令收到相同 ID 的成功 ACK 与匹配 BLE 状态；单样本耗时约 **0.983s**。这是同值命令与回读样本，**不等于真实开关的 P95**。重发同 ID 得到 duplicate ACK，没有重复 BLE 写入。
- 经用户批准，个人 Hooks 只移除本项目 PreToolUse/PostToolUse 各一条，六类重要事件保留，其他 Hooks 完整保留。现有 Companion 已重启，healthz 为 OK。新 Hook 的信任/加载仍由 Codex 客户端管理；未伪造生命周期事件来冒充真实 Hook。
- 用户已实际操作旋钮；MQTT 观察到 ON/OFF、亮度和色温请求均有匹配 BLE 回读。已观测 16 条旋钮命令与 BLE 回读匹配，其中 9 次纯开关样本为 0.974–1.241s，nearest-rank 样本 P95 为 1.241s。这一测量从 broker 观察到 set 开始，未含物理输入处理耗时；尚未达到初期 ≤1s 目标，样本量也不足以代表长期 P95。
- 用户反馈原主页连续卡位不符合开关手感，已改为两端位、一次跨档，并增加实际页面回归。新手感版本已重新烧录，四段写入均通过摘要校验；用户复测确认两端位开关手感、黑屏旋转控灯且不亮屏、黑屏按压只唤醒均正常。按压微旋、队列压力、异常网络与功耗等未逐项确认的场景仍保留待测。

## 实机执行顺序与记录

用户已明确将电流与三组 12 小时续航留到后续，本轮在完成软件、部署和基础操作确认后结束。下列长测计划与未覆盖异常场景保留待办，不宣称续航达标。

先确认各板用途和串口，私下保留对应整片 Flash/NVS 备份，再刷对应镜像。不得把密钥、设备标识、NVS、原始日志或私有固件提交到仓库。本轮通过只读芯片识别确认 ESP32 网关为 4MB、ESP32-S3 旋钮为 16MB；用户确认继续部署后，分别保存完整 Flash 备份并核对分区一致，再进行烧录。网关三段、旋钮四段写入均通过摘要校验，NVS 分区未被擦写。旋钮初次分块备份仅 NVS 中 28 字节随旧固件运行变化；停止固件运行后刷新该块，整片 16MB 已与芯片 MD5 匹配，并另存 SHA-256 清单。私有镜像、原始日志和 Hooks 备份均在仓库外。

先测 T02/T05/T10–T19，再测 State/ACK、断线恢复与 Codex；不要在方向或电机唤醒异常时进入长时间电池测试。BLE 端到端延迟应记录样本数及 P95（初期目标 ≤1s），并区分冷重连和已连接状态。

600mAh / 12h = 理论平均 50mA；建议总平均测量目标 35–40mA 以留余量。整板电池侧电流才有意义，不能以芯片规格或 RGB 熄灭推算整机续航。至少完成三组真实使用：20–50 次开关/天、约十分钟精调或浏览、少量 Codex 通知，其余 DARK。安全地在低电量保护前停止，不深度过放。
